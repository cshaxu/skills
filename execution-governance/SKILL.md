# 实施治理

## 职责边界

本 skill 定义请求受理、任务状态机、任务简报、验证、复盘和闭环。项目的文档目录、文件命名、任务历史和状态面板位置由 `$documentation-governance` 及项目自身文档规范决定；本 skill 引用这些位置，不另行定义文档布局。

## 请求受理与确认

- 当用户只是提问、讨论或头脑风暴时，直接回答，不虚构任务。当用户提出一个或多个要实施的结果时，将原始请求保存在任务记录中，不得只保留实施者的概述。
- 在实施前，结合适用规范、仓库当前状态和已知风险理解请求。将其拆分为有序的任务和子任务，为每个项写明完成条件、验收证据、退出标准和非目标。
- 在开始任何实施性变更前，请求用户确认任务拆解和实施。已明确设定的 goal、已批准的任务包或其他明确授权可作为该确认的证据。

## 任务简报

- 实施前建立任务简报：上下文、处理方法、目标、非目标、基线、受影响边界、适用规则、验证方法、风险、退出条件和停止条件。
- 使用需求台账保留每条原始请求，并将它们映射到一个负责人、状态和证据。对依赖和风险单独建表，不得在拆解中丢失原始含义。
- 默认一次只有一个活跃子任务。如需并行，先定义非重叠的所有权、资源和验证范围。
- 未编号候选项保留在项目的 Queue；只有获得批准并进入唯一活跃状态面板时，才依项目编号政策分配下一个线性任务编号。此时创建项目指定位置的任务历史记录并写入需求台账、调研报告、任务简报等。如果任务不予实施，则应当及时清除该记录。

## 状态与验证

```text
受理 -> 已规划 -> 活跃 -> 已实现 -> 已验证 -> 已闭环
                         |             |              |
                         +-> 已阻塞   +-> 已延期 <-+
```

- “已实现”不等于“已验证”。已延期的项目需要所有者批准、原因、重新准入触发条件和债务记录。
- 设计工作必须在实现前产出有界的任务拆解、验收条件和停止条件。不要因为已有支撑代码就提前启动后续里程碑。
- 根据风险运行最精准相关的构建、测试、静态分析、系统验证或人工审查。确定每项检查的对象和它能证明的事情。
- 触及共享命名空间、注册表、路由、冲突裁决或 dispatch 时，任务简报必须列出唯一权威、全部生产注册/调用点、公开操作路径和禁止旁路。验收证据必须证明重复绑定不会改变既有状态，内部和公开路径到达同一权威，并包含覆盖全量调用点的静态或清单检查。
- 结构性工作默认保留已确立的用户可见行为。改变这些行为需要明确批准和前后对比证据。架构声明以实测行为和有针对性的验证为准，不以意图代替证据。

## 改动纪律

- 保持改动范围精准。文件搬迁时保留溯源；若意图是搬迁而非重写，使用版本控制的 move 操作，修复依赖后验证再继续。
- 为变更运行最精准相关的格式化、静态分析、构建和行为检查。触及共享契约或用户可见风险时扩大验证。
- 修复一个问题后，扫描代码库中具有同一成因的类似缺陷。一并修复或明确记入债务，不要沉默遗留。
- 已知但未处理的工作必须进入债务台账，包含优先级、负责人、准入触发条件和目标。源码注释不得是唯一记录。

## 发现、复盘与同类扫描

- 在实施中发现的架构、编码、测试或仓库内部问题必须记入项目指定的任务历史记录：触发条件、受影响范围、证据、初步原因和处理决策。
- 当问题范围清晰、风险可控且能在当前任务的完成条件内验证时，将其新增为子任务一并修复，更新需求台账、验证证据和任务日志。
- 当问题需要不清晰的调研、不成比例的工作量、公开契约变更或架构重新设计时，不得悄然扩张当前任务。完整记录问题、风险和建议的准入条件，交给后续设计或任务决策。
- 任务完成前进行复盘：分析本次发现如何避免在后续任务中重现，并扫描代码库寻找同类问题。将结果记入项目指定的任务历史记录，或在原则具有广泛复用价值时抽象入仓库自身的架构或编码规范，并链接回对应任务日志。

## 工作环境与闭环

- 为需要保留的产物、日志、证据和第三方资源定义项目策略。设计或文档任务不得为满足形式而伪造实现或运行证据。
- 清理当前任务不再需要的临时产物、日志、跟踪和测试输出。对可无界增长的诊断输出事先定义时间、大小、无进展和清理预算。
- 在声称完成前，必须重读保存的原始用户请求，将其逐条与需求台账、实施结果和验证证据比对。每条请求必须已验证完成或有所有者批准的延期决定；任何遗漏、静默改义或仅“已实现”的条目都禁止任务关闭。
- 闭环前逐条审计：每条需求是否已验证或已批准延期？含义是否在拆解中改变？适用规则是否保持？状态、链接、债务和证据是否更新？剩余项是否是明确债务而非未完成工作？
- 闭环后出具任务汇报：将原始请求映射到完成结果与测试证据，列出实施中的额外发现及处理、延期或新债务，并说明复盘结论和已更新的仓库规范（如有）。任务审计结果和任务汇报应当写入项目指定的任务历史记录中。
