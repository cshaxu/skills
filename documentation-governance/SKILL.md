# 文档治理

## 前置与边界

本 skill 只决定文档的权威、结构、链接、历史和可发现性。它不决定架构、源码或任务执行规则：需要这些决策时，分别使用 `$architecture-governance`、`$coding-governance` 或 `$execution-governance`。

## 当前权威

- 每个主题只保留一份当前权威。使用链接而不是复制；当前文档说明承诺、边界、决策和验收条件。
- 每个仓库必须维护自己的具体、当前的“架构规范”、“编码规范”、“文档规范”和“实施规范”。它们必须写明该仓库的实际决策、边界和规则。
- 这四份仓库规范可以引用对应的共享 skill 来避免复制通用原则，但不得以 skill 替代仓库对具体目录、技术选型、公开契约、流程、验收标准和例外的声明。
- 在四份仓库规范的基础上，为系统设计、路线图、债务和执行工作流程指定权威位置。项目可根据规模合并或拆分主题，但必须明确每项职责的归属。
- 任务包、状态、验证、延期和闭环只由实施规范权威化。本文档 skill 只规定这些记录的目录、命名、链接和归档位置，不复制或另行定义其生命周期规则。
- 源码、许可证、第三方依赖、资产和发布策略应有各自的当前权威。文档 skill 只要求它们可定位、被链接且不与其他文档冲突。

## 结构与维护

- 仅在权威、受众或生命周期真正不同时拆分文档。不要因为一次讨论、一个子任务或一个已完成行动就创建独立当前文件。
- 当权威文档移动、合并或退役时，更新直接链接。定期审计重复权威、失效状态、损坏链接、冲突术语和无所有者需求。
- 将运行状态与长期设计分开。历史文档解释原因但不覆盖当前规则；仅在实施 skill 确认工作已闭环后归档细节。

## 文档规范实施细则

每个项目内，文档的目录和文件结构应当遵循以下刚性规范，除非项目自身以明确治理决定替换它。`docs/README.md` 是唯一入口，只说明阅读顺序和每份当前权威的位置。

1. /docs/rules 用于存放所有规范类文档；里面只有这几个文件：

DOCUMENT.md - 对本文档治理技能的引用，加上项目自身的额外文档规范和细则；
EXECUTION.md - 对 `$execution-governance` 技能的引用，加上项目自身实施规范的细则；
ARCHITECTURE.md - 对 `$architecture-governance` 技能的引用，加上项目自身的额外架构规范。它只定义项目如何作出和维护架构决定，不包含项目本身架构设计；必须链接 `../design/ARCHITECTURE.md`；
CODING.md - 对 `$coding-governance` 技能的引用，加上项目自身的额外代码规范。它只定义项目如何编写、审查和验证代码，不包含项目本身代码结构；必须链接 `../design/CODING.md`。

2. /docs/design 用于存放宏观的架构设计和代码目录文件结构的设计；里面只有这几个文件：

GOAL.md - 用于阐述项目要实现的宏观战略目标；
ARCHITECTURE.md - 用于阐述项目的组件划分、模块划分，划定各组件、各模块的目的、能力、边界和外部交互行为，不涉及内部细节的设计；它是当前项目设计，必须链接 `../rules/ARCHITECTURE.md`，但不重复或改写通用架构规则；
CODING.md - 用于规定项目的代码的目录结构、文件命名规范、文件分拆合并挪动的标准、代码结构的宏观设计；它是当前项目设计，必须链接 `../rules/CODING.md`，但不重复或改写通用编码规则；
UI.md - 用于规定项目的产品的用户交互方式和界面的宏观设计和主要产品界面。
ROADMAP.md - 规定里程碑的划分，以及各里程碑分别要完成目标；不安排具体实现步骤。

3. /docs/history 用于存放所有任务的历史记录，每一个任务有各自的文档，以 "任务编号-任务介绍.md" 为文件名，不得出现其他文件。通常来说，由于任务是线性执行，已关闭的任务，只要不是最后一个，便不再写入；以项目规范为准，允许例外。该文件存放任务启动时的原始需求台账、调研报告、任务目标、非目标、实施细则和退出标准；任务关闭时的总结汇报；以及项目编号政策允许的后续修复原因和结果。

4. /docs/TODO.md 用于存放未解决债务台账。储存用户提供的灵感、短期、近期、中期、长期目标和一定程度的细节，主要目的是为任务的计划提供路线图指南。记录尚未开始、尚未明确排期，或不应偷偷混入当前任务的风险/欠账。每项应有优先级、边界、准入条件和风险。

5. /docs/QUEUE.md 用于存放当前已排好的未编号候选任务；按照优先级排序，以便于即时更新、加入任务、删除任务等队列维护工作。候选项只有获得批准并进入 /docs/STATUS.md 时才按项目的编号政策分配下一个线性任务编号；已关闭任务和当前活跃任务以外的记录不得占用任务编号。

6. /docs/STATUS.md 是运行中的控制面板，只回答三件事：现在唯一活跃的任务/子任务是什么；当前技术基线、artifact、测试状态是什么；最近少量闭包摘要。它不应保存长期计划、完整设计或完成任务详情。活跃任务包在这里，是为了保证“唯一活动任务”可见。当任务结束时，实施规范规定的记录移入相应的 /docs/history 任务记录。

7. /docs/etc 用于存放所有无法被前面方法正确分类的文档，应当谨慎小心。如果要使用，需要明确获得用户的批准，并记录文档所有者、用途、预期归属或退役条件；它不是永久扩展主文档集合的快捷方式。
